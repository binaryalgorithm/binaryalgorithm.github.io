Working assumptions, and why shifted repeat patterns mean shared plaintext

Treated as settled

  • Values. Read each triangle of 3 eyes as a base-5 number. Exactly one eye numbering and reading order gives every value 0–82 with no gaps.
  • One cipher and one key for all 9 messages. All 9 share their opening values, and long shared stretches line up at the same positions.

Best-fit cipher model: a stateful "deck" cipher (group autokey on 83 symbols)

  • An 83-card deck. Each plaintext letter outputs one card and rearranges the deck by a rule that depends only on positions in the deck, never on which card is where. The deck state carries forward from letter to letter.
  • Fits all of these:
    • flat value frequencies;
    • no value ever follows itself (0 in about 1000);
    • shifted copies of passages;
    • the relabelling between copies doesn't commute, which rules out simple substitution, Vigenère and other periodic ciphers, progressive and autokey ciphers, and plain or flipping cipher wheels.
  • Excluded by our own exact test: an affine "multiply-and-shift" state (the AGL(1,83) group). No consistent fit to the copy pairs.
  • Labels (column 0) and the grey slots move the deck only by their length (or not at all), never by their content. Shared text locks back exactly after them every time.

Why matching repeat spacing means the same plaintext

  • The deck rule only moves positions. So the same run of plaintext, started from two different deck states, gives two outputs that are one fixed relabelling of each other. Wherever one copy repeats a value, the other copy repeats a value with the same spacing, but the values differ (the coloured letters A, B, C… in the grid). Different plaintext gives unrelated repeat patterns.
  • A chance match is very unlikely. We compared each message against a reversed and rotated partner, which keeps value frequencies but has no real copies. Across 174,000 such alignments, none had 3 or more matched repeat pairs, with zero mismatches, inside a 40-value window.
    • Links with 3 or more pairs are therefore treated as real. A highlight runs only from a passage's first matched repeat to its last: a repeat proves the text between its two ends, nothing before or after.
    • 2-pair links count only when three messages agree on consistent offsets (passage B in W2/E3/W3).
  • This says the plaintext is the same. It says nothing about what that plaintext is.
